## Objective and acceptance

Generate the approved [basic car source](../fixtures/car/basic_car.fs) as a **repeatable native, human-editable Onshape feature tree**. Acceptance requires all 22 planned features (7 variables, 5 planes, 5 sketches, 5 extrudes), eight resulting solids matching the approved local 114 × 180 × 64 mm bounds, source parametric expressions and dependencies, one verified edit and regeneration of the resulting car, preservation of unrelated feature identities, and a repeatable CLI/MCP workflow without manual modeling steps. Apply the [acceptance gates](ACCEPTANCE.md), including separate definition, regeneration, geometry, and human-editability evidence. Only after the full native creation path is proven may the authorized existing generated car be replaced. The later `cadder` launch condition and exact robotics brief are recorded under [Queued future requirement](verification/native-begin-top-trial-2026-11-13.md#queued-future-requirement); robotics work has not started.

**Ultimate delivery:** connect the existing MCP and agent plugin/skill package to a deterministic path from FSGen source through local OpenCascade validation to ordinary browser-bridge creation of native, human-editable Onshape CAD and assemblies. The agent supplies design intent; geometry and feature operations follow the validated source and supported compiler, without an AI-driven geometry loop or REST write fallback. The proving order remains plate → full native car → root's new `cadder` design; the older printed robot is a separate deferred regression with different axes.

**First delivery checkpoint:** one reusable entry point takes an existing FSGen source through local OpenCascade validation, then creates its native Sketch and Extrude from an **empty test Part Studio without manual modeling**, and verifies saved geometry plus human editability. The [minimal plate](../fixtures/native/minimal_plate.fs) is the proving example, not a fixture-specific implementation: supported operations are compiled from source and unsupported ones fail explicitly. Shared completion and recovery must distinguish a saved result from a timeout or restart and must never duplicate an uncertain creation. After this clean plate flow passes, extend the same path to the car's variables, planes, circles, expressions, 22 features and eight parts, then verify an edit and replace the authorized old generated car; root launches `cadder` only after that full car gate.

The focused reliability and normal-editor sequence are documented in [CAD research](CAD-RESEARCH.md); the live gates below take precedence over any proposed fallback.
