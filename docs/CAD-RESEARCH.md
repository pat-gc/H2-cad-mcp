## What established projects do

- **FreeCAD** models linked document objects, recomputes changed features with an error result, and exposes separate undo transaction and document save operations. Its modeling guidance recommends base geometry and datums over references to generated faces where practical, even with topological naming mitigation. For H2 CAD, this supports making dependencies explicit and treating draft completion, saved definition and regenerated output as distinct checks. FreeCAD’s local transactions give no evidence of atomic rollback in Onshape. [Document API](https://freecad.github.io/SourceDoc/d8/d3e/classApp_1_1Document.html) · [Document object API](https://freecad.github.io/SourceDoc/d2/de4/classApp_1_1DocumentObject.html) · [Topological naming guidance](https://github.com/FreeCAD/FreeCAD-documentation/blob/main/wiki/Topological_naming_problem.md)
- **CadQuery and build123d** make construction planes explicit. CadQuery can tag a workplane for later reuse, and build123d describes selection using topology, geometry and provenance. Keep the current FSGen/OpenCascade path for local coverage and geometry checks. Apply the reference discipline to the compiled source graph and leave live selection resolution to the editor adapter. Plane display names alone are insufficient across systems. [CadQuery workplanes](https://cadquery.readthedocs.io/en/stable/workplane.html) · [CadQuery plane axes](https://cadquery.readthedocs.io/en/latest/_static/cadquery_cheatsheet.html#named-planes) · [build123d plane placement](https://build123d.readthedocs.io/en/stable/key_concepts_algebra.html) · [build123d topology selection](https://build123d.readthedocs.io/en/stable/topology_selection.html)
- **Onshape** stores the Part Studio as a feature list and regenerates it when the list changes. Persistent feature and sketch-entity IDs are distinct from geometry IDs, which can change across revisions. A geometry reference can map to zero, one or several entities after an edit. FeatureScript’s `qSketchRegion` expresses the dependency on the producing sketch and can yield several regions. The official feature endpoint illustrates definition, feature status and revision metadata. Those semantics are useful as a reference for evidence in H2 CAD’s existing browser-authenticated path. The documentation does not establish equivalent guarantees for the private editor protocol. [Architecture](https://onshape-public.github.io/docs/api-intro/architecture/) · [Associativity](https://onshape-public.github.io/docs/api-adv/associativity/) · [FeatureScript query library](https://cad.onshape.com/FsDoc/library.html) · [Feature API](https://onshape-public.github.io/docs/api-adv/featureaccess/)
- **QCAD and LibreCAD** offer useful precedents for 2D geometry, drafting and snapping. Their documented scope gives limited guidance on constrained sketch-to-solid dependencies, remote regeneration or collaborative save confirmation. [QCAD features](https://qcad.org/en/features/) · [LibreCAD manual](https://docs.librecad.org/en/latest/about/index.html)

## Recommended order

1. **Prove live read readiness before investigating Save.** Have the existing inspection path report bridge pairing, exact-tab attachment, Onshape editor service connection, and a bounded fresh semantic read for the requested document/workspace/element independently. Treat a visible disconnect as a readiness failure and cached feature lists as historical observations. Log the first failed stage and elapsed time. After the authorized normal reload, make one read-only attempt on the exact target. If it returns fresh state, run the already-reviewed exact-result reconciliation. If it fails, preserve the guard and record the failed stage. A UI check of the relevant tab’s Versions and history can corroborate a persisted change if the normal editor is online. Use feature readback to establish identity, contents and regeneration. [Onshape history](https://cad.onshape.com/help/Content/Document/document_management.htm) · [History filters](https://cad.onshape.com/help/Content/Document/versions_and_history.htm)
2. **Share one positive completion path for Sketch and Extrude.** Reuse the journal, exact target check and existing verification logic. Persist the operation and expected native identity or uniquely provable change before the relevant dispatch, then retain a receipt when observed. After Save, a fresh read should establish the intended definition and dependency, matching exact native identity, consistent revision evidence, idle editor, and successful regeneration. Keep part measurements and editability as additional acceptance evidence. A missing or delayed acknowledgement remains unknown until positive proof. A changed revision alone can reflect another edit, and a successful client preflight leaves a concurrency window. An offline fault experiment should cover failure before dispatch, response lost after Save, reconnect/readback failure, and mismatched identity or definition. Require zero replay of ambiguous writes and a single feature after verified recovery. AWS’s production pattern permits retry through an idempotency token only where the receiving service implements the contract. H2’s local operation ID supports correlation and reconciliation. [AWS Builders’ Library](https://aws.amazon.com/builders-library/making-retries-safe-with-idempotent-APIs/) · [Onshape architecture](https://onshape-public.github.io/docs/api-intro/architecture/)
3. **Resolve two semantic references through the ordinary editor.** Use the fixture’s built-in `Top` datum identity and confirm a unique live plane binding, including its frame where the read path exposes it. The prior trial got `Top.planeOp` from the ordinary click, while programmatic `HTMLElement.click()` opened a draft without binding Top. In a fresh disposable studio after the current guard is resolved, make one attempt using the reviewed automatic Top path. Record draft ID, binding/readback, and saved status as separate observations. For Extrude, use the just-verified native Sketch ID, require the one enclosed source region for the plate, and verify live provenance such as the sketch’s imprint operation. Treat absent or ambiguous bindings as a diagnostic. A bounded fallback experiment is the documented Extrude action on the active Sketch toolbar, which accepts the sketch and preselects its closed regions. It crosses two feature boundaries and can select multiple regions, so prefer separate verified Save and region binding. Keep this fallback limited to a unique validated region and account for both mutations if it is tried. [Sketch basics](https://cad.onshape.com/help/Content/Sketch/sketch_basics.htm) · [Sketch toolbar behavior](https://cad.onshape.com/help/Content/Sketch/sketch_tools.htm) · [Extrude behavior](https://cad.onshape.com/help/Content/PartStudio/extrude.htm)
4. **Prove the normal entry point before expanding coverage.** Run the same compile, validate, apply and verify flow from an empty authorized disposable Part Studio. Require exactly two editable native features with the intended dependency, one regenerated 40 × 20 × 5 mm solid, and an ordinary edit/restore on the same feature IDs. A 5 → 6 → 5 mm depth edit should produce 4,000 → 4,800 → 4,000 mm³ for this fixture. A second empty-studio run with different supported dimensions can catch fixture hardcoding. Then add car capabilities in dependency order through the same pipeline and require the existing 22-feature, eight-solid, 114 × 180 × 64 mm, expression and identity-preservation gates before touching the existing generated car.
