# Applied-invalid native sketch: exact recovery

The repaired source trial submitted one native sketch change in the authorized temporary Part Studio. It produced four 40×20 mm line definitions and eleven constraints, but Onshape displayed `Some external references are missing.` and the constraint graph returned no constraints or references. The journal operation `sketch-d9d02a9ba8b44bdea72b4bb67281c7e1` and bridge write guard remain unknown. This is an **applied invalid sketch**, not a pre-dispatch rejection or a verified model.

The observed manual UI rectangle had an empty serialized `externalSecond` query and a valid origin solver reference. The source-generated sketch had the same visible query shape but no solver binding. That empty query is not reusable as an origin selector; the generator must acquire origin semantics through a supported editor operation or replace it with proven internal constraints. Once Onshape closed the failed edit, its saved red feature returned a generic sketch response with no constraint graph fields; the classifier records the graph as unavailable, not solved or empty.

Patch 12 adds a two-phase recovery. First, `h2cad experimental-classify-known-invalid-sketch sketch-d9d02a9ba8b44bdea72b4bb67281c7e1 --tab-id <exact-tab> --bridge-config <paired-config> --journal <same-pinned-journal>` reads the exact current tree and sketch response, confirms the applied source definition, unchanged unrelated tree, known invalid revision, and either the active empty graph or the saved feature's unavailable graph. It stores `applied_invalid` evidence while the journal and bridge guard **remain blocking**.

The editor may finish the failed edit despite the page timeout. The classifier accepts either that exact active feature or the same saved red feature with `editingFeatureId=null`; it records which lifecycle was seen. After Astra review, the tester removes only that identified red temporary Sketch 1 using the normal editor red X if still active, or the normal feature-tree Delete action if saved. This is a corrective UI action on the disposable test target; it does not touch the existing car. The tester then runs `h2cad experimental-finalize-known-invalid-sketch-cancel sketch-d9d02a9ba8b44bdea72b4bb67281c7e1 --tab-id <exact-tab> --bridge-config <paired-config> --journal <same-pinned-journal>`. Despite its historical command name, the finalizer accepts either UI removal method solely by independent state. It checks the sole unresolved row, prior `applied_invalid` evidence, connected idle editor, new revision, exact default tree obtained by removing the failed sketch from its prewrite tree, and no pending bridge command. Only then does it record `applied_invalid_rolled_back` and clear the persisted write guard. Any mismatch leaves both barriers active.

Before the finalize command, the tester stages reviewed fork patch 12 and restarts only the paired Python broker; the current extension can serve the read-only state. There is no replay or automatic mutation. A future source-generated origin anchor requires a fresh normal UI evidence sample for internal X/Y coordinate dimensions or a supported Fix constraint, followed by a new separately reviewed candidate and one controlled trial.
